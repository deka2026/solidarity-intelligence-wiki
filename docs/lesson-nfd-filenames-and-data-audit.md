# 레슨 — NFD 한글 파일명 함정과 "리스트 전수 집계 먼저" 원칙

> 작성일: 2026-07-24 | 맥락: 전남광주 50MW 시범사업 계획서 작업

## 1. 한글 파일명이 NFD(자모 분해형)면 문자열 매칭이 전부 실패한다

- 증상: `Get-ChildItem`에는 보이는 파일이 경로 직타(`Open("...비탈면144...")`)와 `-like "*비탈면*"` 매칭에서 모두 실패. 에러는 "파일을 찾을 수 없습니다"라 원인을 알기 어려움
- 진단: `$f.Name.Length`가 눈에 보이는 글자 수보다 훨씬 크면(예: 28자 → 45) NFD다. macOS·텔레그램 경유 파일에서 흔함
- 우회: **파일명을 타이핑하지 말고** `Get-ChildItem`으로 FileInfo 객체를 잡아 `$f.FullName`으로 열기. 매칭이 필요하면 한글 대신 **ASCII 숫자 패턴**(`-match '144'`, `'2,333'`)을 쓰기
- 근본 교훈: "파일이 분명 있는데 못 연다"면 인코딩(NFC/NFD)부터 의심

## 2. 자료가 "없다"는 결론도 데이터다 — 전수 집계 먼저, 서술은 그 다음

- 고속도로 비탈면 리스트(144개소)가 있었지만 **전남 물량은 0건**(호남권 5개소 전부 전북 완주), 폐도도 순천 1곳 0.7ha뿐이었다
- 리스트가 존재한다고 "폐도·비탈면·폐철로 활용"을 본문에 병렬로 쓰면 과장이 된다 — 전수 집계 후 "비축농지가 주력, 나머지는 보조"로 서술을 바꿨다
- 원자료마다 **밀도 가정이 다르다**(GIS 분석 0.8MW/ha vs 공사 대장 1MW/ha vs 비탈면 파일 8.26㎡/kW) — 표마다 기준을 주석으로 명시해야 수치 충돌로 보이지 않는다
- 대장류는 범위 한정을 확인할 것: 농어촌공사 저수지 대장에 나주호·장성호 같은 대형 댐이 아예 없었다. "대장에 없음 = 존재하지 않음"이 아니다

## 3. 자료를 못 찾았을 때는 조사과업으로 처리하고 진행한다

- 1차 작성 시 6종 리스트를 로컬에서 못 찾음 → 멈추지 않고 "1단계 전수조사 과업 + 공공데이터 출처 명시"로 계획서를 완성하고, 못 찾았음을 사용자에게 보고
- 사용자가 실제 파일 경로를 주자 붙임을 "조사 계획 → 분석 결과"로 교체 — 문서 구조를 처음부터 교체 가능하게 짜두면 갱신 비용이 작다
