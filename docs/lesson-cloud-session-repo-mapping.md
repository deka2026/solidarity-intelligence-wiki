# 레슨 — 클라우드 세션에서 "그 폴더에 저장해"를 저장소로 번역하기

> 작성일: 2026-09-19 | 사례: 세무사 인터뷰 질문지 hwpx를 "햇빛발전협동조합 업무자동화 사이트 폴더"에 저장 요청

## 무슨 일이 있었나

이전 작업들은 대부분 사용자 PC의 로컬 세션(D: 드라이브, `C:\Users\pc\클로드로컬\…`)이었다. 이번은 **클라우드 세션**인데 사용자는 같은 감각으로 "사이트 폴더에 저장해"라고 했다. 클라우드 세션은 PC 폴더에 닿을 수 없고, 사용자가 말한 폴더 이름("햇빛발전협동조합 업무자동화 사이트")은 어떤 저장소·문서에도 그대로 존재하지 않았다.

## 교훈

1. **세션이 어디서 돌고 있는지를 첫 줄에 밝혀라.** "이 세션은 클라우드라 PC 폴더에는 못 쓴다"를 먼저 말하면 사용자가 목적지를 저장소로 바꿔 말해 줄 수 있다. 이번엔 조사 후에야 밝혀 한 라운드를 더 썼다.
2. **폴더 이름은 정확히 일치하지 않는다. 핸드오버 문서로 실체를 찾아라.** "햇빛발전협동조합 업무자동화 사이트" → 리포의 [[handover-sunvillage-network-merge]]가 "햇빛소득마을 종합 업무도우미 = `poomasi-site/sakyowon/sunvillage.html`", "통합본 = 로컬 `sunvillage-network/` (저장소 없음)"임을 알려 줬다. `list_repos`로 조직 저장소 21개를 훑고 이름이 비슷한 4개를 얕은 클론해 `<title>`을 grep한 것으로 후보를 하나로 좁혔다.
3. **후보가 하나로 좁혀져도 "다른 저장소에 푸시"는 사용자 결정이다.** 지정 브랜치 밖 푸시는 명시 허락이 필요하다. AskUserQuestion으로 물었고, "선호 없음" 응답을 받은 뒤 진행했다. 응답이 없었다면 다운로드 URL만 주고 멈추는 게 맞다.
4. **남의 거버넌스가 있는 저장소는 그 규칙의 가장 보수적인 경로로.** poomasi-site는 "main 직접 푸시 금지, 패미는 staging만, 지미가 머지"다. staging도 남의 작업 브랜치이므로(main과 서로 1커밋씩 어긋나 있었음) **새 날짜 브랜치**(`sakyowon-tax-interview-hwpx-20260917`)에만 올리고, 링크 추가 같은 부수 편집은 하지 않았다. 반영은 그 저장소 담당의 몫으로 핸드오버에 남겼다.
5. **add_repo → 반드시 clone → register_repo_root 순서.** 읽기 전용(`access:"read"`)으로 붙인 공개 저장소는 `/home/user/<owner>/<repo>`에, 푸시 권한으로 붙인 저장소는 `/home/user/<repo>`에 클론된다. 경로가 다르니 읽기용 클론을 푸시용으로 재사용하려 하지 말 것. 저장소마다 클론은 한 번에 하나씩(동시 2개 제한, 429).
6. **한글 프로그램이 없는 환경의 hwpx는 "검증 통과"까지만 말하라.** 스키마·zip·텍스트 복원은 확인했지만 렌더링은 못 봤다는 것을 산출물 보고에 명시했다. 이전 레슨([[lesson-source-attribution-honesty]])과 같은 원칙.

## 다음에 바로 쓰는 체크리스트

- [ ] 세션 종류(로컬/클라우드) 먼저 말하기
- [ ] 목적지 폴더 이름 → 리포 핸드오버·CLAUDE.md에서 실체(저장소/경로) 찾기
- [ ] 후보 저장소는 `list_repos` → 얕은 클론 → `<title>`/README grep으로 확정
- [ ] 지정 브랜치 밖 푸시는 사용자에게 묻기(AskUserQuestion), 무응답이면 URL만
- [ ] 대상 저장소의 CLAUDE.md 거버넌스 읽고 가장 보수적인 브랜치 전략 택하기
- [ ] 못 검증한 것(렌더링 등)은 "못 봤다"고 쓰기
